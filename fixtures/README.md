# Shared fixtures for `urim check`

All three implementations (`packages/js`, `packages/python`, `packages/rust`) run every case in `cases.json` and must produce **exactly** the same exit code and output line.

## Behavior of `urim check <file>` (protocol 0.2, hoshen 2)

Output is one line: `<file>: ok (...)` on stdout with exit 0, or `<file>: error: <problem>` on stderr with exit 1. Usage errors exit 2. [`CONTRACT.md`](../CONTRACT.md) has the exact messages; this is the outline.

Checks run in this order. The first failure wins.

1. Read the file and decode it as UTF-8 (strict); a leading BOM is ignored. Failures: `cannot read file`, `file is not valid UTF-8`.
2. Parse exactly one YAML document using **YAML 1.2 core-schema** scalars (`yes`/`no`/`on`/`off` are strings, timestamps are strings). Integers follow the core schema (`0x`/`0o` forms allowed) except that decimal integers with leading zeros (`01`) stay strings. Duplicate keys, multiple documents, sequence/mapping keys, and integers outside the 64-bit range (−2^63 to 2^64−1) count as parse errors. Failure: `invalid YAML` (parser details are left out so the messages match across languages).
3. The root must be a mapping. An empty file counts as null. Failure: `root must be a mapping`. The version key's pre-0.1 name is refused here, before anything else (C-093).
4. **Lockfile:** applies if the root has `hoshen` (C-046 is the order).
   1. `hoshen` must be an integer (booleans and floats such as `1.0` are rejected), must not be 1, a format that was never released (C-094), and must be in the supported set `{2}`.
   2. `urim` must be present and pass the version gate: a `"MAJOR.MINOR"` string equal to `0.2` (C-100).
   3. The closed hoshen 2 schema: unknown, removed and missing keys, kinds, formats and bounds (C-095, C-096).
   4. The seal: `integrity` matches the RFC 8785 (JCS) form of the rest of the document (C-098).
   5. Lockfile rules: `active` and `standby` name declared targets (C-099).

   OK output: `ok (lockfile, hoshen N, urim V)`.
5. **Contract:** applies if the root has `urim` (but not `hoshen`) (C-057 is the order).
   1. The version gate (C-100).
   2. The closed contract schema, then formats and bounds (C-095, C-096).
   3. Contract rules: experimental types declared, policy and eval references, requires vs prefers, emulations (C-097).

   OK output: `ok (contract ID@VERSION, urim V)`.
6. Anything else: `not a urim document: expected a lockfile with 'hoshen' or a contract with 'urim'`. That includes provider descriptors, which this release does not check.

## Files

- `cases.json`: file-level cases (`urim check <path>`). Each case has the `id` of the [`CONTRACT.md`](../CONTRACT.md) entry it pins. Paths are relative to this directory; some point at `../spec/examples/`.
- `cli.json`: argv-level cases (flags, usage errors, stdout vs stderr, verbatim paths, Planned commands that exit 2), run with this directory as cwd.
- `valid/`, `invalid/`: hand-written inputs.
- `mutations/`: one-change variants of the spec examples, generated by `scripts/gen-mutations` (do not edit by hand). Their expected outputs are in `cases.json`.
- `sealed.txt`: lockfiles whose `integrity` `scripts/seal-fixtures` keeps current.
- `formats.json`: shared verdicts for every string format (C-096).
- `jcs/corpus.json`: the golden RFC 8785 corpus (C-098), checked by `scripts/check-jcs-corpus`.
- `hostile/` + `hostile.json`: hostile inputs run by `scripts/hostile.py` under time and memory bounds.
- `divergences.json` + `divergent/`: inputs where the ports knowingly differ (CONTRACT.md section D, e.g. D-015). Each port pins its own behavior; `scripts/parity.sh` skips them.

`scripts/parity.sh` runs all three CLIs over every `cases.json` and `cli.json` case and requires byte-identical output.
